## 서체·위계·애니메이션 재수정

2026년 10월 22일 사용자 후속 요청을 반영했다.

- 국문 Pretendard는 유지하고, 영문 Manrope를 Inter로 변경했다. 공식 배포처의 가변 서체와 SIL Open Font License를 로컬에 저장하고 배포 결과에 포함한다.
- PC 메뉴는 16 → 17px, 일반 본문은 17 → 16px, 메인 소개 문장은 20 → 18px로 조정했다. 일반 본문의 행간은 1.7로 통일했다. 모바일 일반 본문은 16px를 유지했다.
- 메인 제목의 첫 줄은 700, 둘째 줄은 600으로 보강했다. 섹션 제목은 36px를 유지하면서 700으로 보강했다.
- 메인 문구·설명·버튼의 순차 등장과 섹션 제목·사진·카드의 스크롤 등장 효과를 복구했다. 첫 화면은 760ms, 일반 요소는 680ms, 이동 거리는 18–24px이다. 한 번 보인 요소는 다시 스크롤해도 재생하지 않는다.
- 내용을 숨기는 기본 스타일을 사용하지 않는다. 애니메이션 API가 없거나 움직임 줄이기가 켜져 있으면 내용이 그대로 표시된다. 재생 도중 움직임 줄이기를 켜면 효과를 중단한다.

실제 인앱브라우저에서 첫 화면 요소별 서로 다른 불투명도·이동값과 실행 상태를 확인했고, 스크롤로 새 섹션에 진입했을 때 등장 효과가 실행된 뒤 완료되는 것을 확인했다. 움직임 줄이기 초기 설정·실행 중 설정 변경·API 미지원·한 번만 재생·등장 시차는 실제 공통 스크립트를 모의 환경에서 실행해 별도로 검사했다.

서체 교체 후 한·영 14개 페이지 × 6가지 화면 폭(360·390·768·1,024·1,440·1,920px), 총 84개 조건을 다시 검사했다. 문서·주요 텍스트 요소의 가로 넘침, 대표 제목의 추가 줄바꿈, 첫 화면 이미지 오류가 없었다. 원본 검사 결과는 [화면 폭별 기록](typography-viewport-checks.json)에 보관한다. 기존 자동 테스트 9개와 파일 공백 검사를 통과했다.

## 단색 심벌 적용

홈·회사소개에서 사용하는 세 이미지를 전체 홈페이지의 사진·타이포그래피에 맞춰 작은 남색 단색 심벌로 정리했다. 국문·영문에 공통 적용한다.

- 지구본과 연결점 / 자료와 돋보기 / 두 말풍선의 소재를 유지했다. 원형 배경과 하늘색 채움을 제거하고, 겹친 문서·원두·작은 점 등의 세부 요소를 줄였다.
- SVG는 64×64 좌표계, 남색 `#072340`과 투명 영역만 사용한다. 기본 선 굵기는 2.4이며 작은 크기에서도 형태가 선명하도록 맞췄다. 최초 라인 시안은 `docs/design/`에 보관한다.
- PC는 72px, 태블릿·모바일은 64px로 표시한다. PC에서 심벌과 제목의 간격은 20px다. 모바일의 심벌·문구 좌우 배치도 64px 열에 맞췄다.
- 일러스트 영역의 배경 박스·구분선 없이 정렬과 여백으로 묶는다. 아래 서비스 섹션의 옅은 배경, 기존 문구·서체·등장 애니메이션은 유지한다.
- SVG 문법·좌표계·사용 색상을 확인했고, 빌드와 파일 공백 검사를 통과했다. 미리보기 서버는 SVG를 `image/svg+xml`로 제공한다.

홈·회사소개 × 국문·영문 × 화면 폭 320·390·768·1,024·1,440px, 총 20개 조건을 실제 인앱브라우저에서 확인했다. 이미지 로딩과 표시 크기가 정확하고 문서·해당 영역의 가로 넘침이 없었다. 그룹 배경도 투명한 것을 확인했다. [검사 기록](pillar-symbol-viewport-checks.json)을 보관한다.

## 문의 저장 연결

고객 문의 입력 → 기존 Supabase `inquiries_web` 저장 요청 → 결과에 따른 안내 표시 흐름을 유지했다.

- 기존 프로젝트와 컬럼을 확인했다. 전화번호가 선택일 때 빈 문자열을 보내 기존의 NOT NULL 컬럼과 호환한다.
- 문의 테이블의 RLS가 활성화되어 있고 기존 익명 INSERT 정책이 있는 것을 확인했다.
- 저장 테이블에 트리거가 없는 것을 확인했다.
- 기존 익명 역할에서 삽입이 가능한지 **롤백되는 트랜잭션**으로 검증했다. 테스트 레코드를 남기지 않았다.
- 데이터베이스 스키마·권한·키를 변경하지 않았다. 기존 공개 클라이언트 키만 유지했다.

운영 저장소에 브라우저에서 실제 테스트 문의를 제출하는 단계는 처음에 자동 승인 검토가 차단했다. 실제 테스트 레코드 생성과 후속 정리에 대한 별도 승인이 필요하다는 이유였다. 이를 우회하지 않고 사용자에게 정확한 작업과 테스트 내용을 제시했다.

사용자가 **테스트 저장과 해당 기록 삭제를 명시적으로 승인**한 뒤 다음 검증을 완료했다.

| 경계 | 결과 | 근거 |
|---|---|---|
| 브라우저 입력 → 제출 | 완료 | 실제 국문 문의 양식에 식별 가능한 합성 테스트 문의 1건 입력·제출 |
| 제출 → 운영 저장 | 완료 | 지정한 회사명·이메일·문의 내용이 일치하는 테스트 기록 1건 확인 |
| 저장 응답 → 화면 | 완료 | 접수 완료 안내 표시, 양식 초기화, 동의 체크 해제, 제출 버튼 복구 확인 |
| 테스트 정리 | 완료 | 승인된 테스트 기록 1건만 삭제, 동일 테스트 식별 조건의 잔여 기록 0건 확인 |

실제 브라우저 제출부터 운영 저장 확인까지의 검증을 완료했다. 운영 도메인 배포는 이 검증과 별개이며 진행하지 않았다.

## 공개 전 남은 사항

1. 개인정보 보관기간·처리위탁·담당자·실제 삭제 절차와 약관 원문 확정. 사용자가 원문이 없다고 알려주어 임의로 확정하지 않았다.
2. 검토 결과를 반영한 뒤 별도 공개 진행. 현재 운영 도메인은 변경하지 않았다.
